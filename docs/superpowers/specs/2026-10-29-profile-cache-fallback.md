# 판매자 프로필 캐시 장애 대응

승인된 범위는 Redis 읽기·저장 실패 시 판매자 프로필을 원본 DB에서 조회하고,
Redis 복구 후 정상 캐시를 다시 사용하는 것이다. 경매 상세가 판매자 조회 실패로
오류 화면이 된 실제 운영 사례를 해결한다.

기존 `MemberService.getMember`의 `member:v2` 캐시에 한해 Spring 캐시 오류 처리기를
등록한다. 조회 실패는 miss로 취급하고, DB 결과를 재저장하다 실패해도 결과를 반환한다.
DB 조회 예외·없는 회원·다른 캐시·evict/clear 오류는 기존 오류 의미를 유지한다.
인증 RedisTemplate, 토큰/인증번호 저장, 프로필 변경·무효화는 이 정책의 대상이 아니다.

비교한 방법: 비즈니스 메서드에 Redis 예외를 잡는 코드는 캐시 프록시 바깥의 오류를
잡지 못한다. 모든 Redis 오류를 무시하면 인증/무효화 의미를 흐릴 수 있다. 따라서
기존 캐시 프록시에 이름과 동작을 제한한 오류 처리기를 붙이는 방식을 선택한다.

캐시 키·회원 정보·값·원문 예외 메시지를 로그에 쓰지 않는다. 기존 TTL, HTTP JSON,
DB 스키마, 재시도/타임아웃 설정은 수정하지 않는다. 추가 서비스나 의존성도 없다.
연결 끊김을 삼켜도 기존 Redis 명령 타임아웃까지의 지연은 있을 수 있다.

실제 Spring 프록시/HTTP/JPA를 사용하는 격리 H2 테스트로 읽기/저장/동시 실패,
캐시 정상 hit와 복구, DB 오류·회원 없음 보존을 검증한다. 다른 캐시와 무효화 오류는
전파되는지도 확인한다. 로컬 Docker는 시작하지 않으며 기존 PostgreSQL 트랜잭션
테스트는 Linux CI에서 실행한다. 운영 Redis를 중단하거나 장애를 주입하지 않는다.
