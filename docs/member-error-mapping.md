# 회원 API 오류 응답 분리

회원이 없는데도 500으로 응답하던 문제를 수정했다. 인증용·공통 예외 처리기가
모두 전역으로 등록되어, 먼저 선택된 처리기의 RuntimeException fallback이 다른
영역의 도메인 예외를 가로채고 있었다. 순서만 뒤집으면 인증 오류가 반대로 500이 된다.

인증 처리기는 `auth.adapter.in.web` 패키지로 제한하고 우선순위를 명시한다.
공통 처리기는 가장 낮은 우선순위의 전역 fallback으로 남긴다.
[Spring의 advice 선택·우선순위 계약](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/web/bind/annotation/ControllerAdvice.html)
을 사용하며 새로운 예외 모델이나 의존성을 추가하지 않는다.

| 상황 | HTTP | JSON code |
| --- | --- | --- |
| 없는 회원 프로필 조회 | 404 | 2002 |
| 닉네임 중복 / 현재 닉네임 재선택 | 409 | 2001 / 2004 |
| 회원 API의 예상하지 못한 DB·런타임 오류 | 500 | 500 |
| 기존 인증 실패 / 잘못된 자격 증명 | 401 | 4204 |
| 기존 인증 API의 예상하지 못한 오류 | 500 | 4903 |
| 만료된 인증번호 | 400 | 4200 |
| 프로필 업로드의 지원하지 않는 파일 형식 | 400 | 902 |
| 인증/인증번호 API의 지원하지 않는 HTTP 메서드 | 405 | 4902 |

오류 응답 필드는 기존 `code`, `message`다. `httpStatus`는 JSON에 노출하지 않는다.
회원 서버 오류의 공개 메시지는 고정 문구이며 DB 연결·SQL 등의 원문 예외 메시지를
반환하지 않는다. 원인 예외는 서버 로거에 남긴다. 일반 오류를 존재하지 않는 회원으로
바꾸거나 예외를 정상 프로필로 반환하지 않는다.

회원 도메인 404/409와 공통 오류 코드가 이제 해당 API에서 일관되게 선택된다.
특히 회원의 일반 서버 오류는 인증 코드 4903이 아닌 회원 공통 코드 500이다.
인증/인증번호의 기존 코드와 메시지는 유지한다. 경로, 성공 응답, DB 스키마,
인증 필터와 비즈니스 규칙은 수정하지 않는다.

프로필 업로드 검증은 회원 오류 계열 902를 사용하되, 제약 조건의 구체적인 공개
메시지(예: 지원하지 않는 이미지 형식)를 유지한다. 예외 원문이나 거부된 입력값을
공개 메시지로 사용하지 않는다. 컨트롤러 선택 전에 발생하는 메서드 불일치는
공통 처리기에서 인증/인증번호의 명시된 경로 6개를 판별해 기존 인증 코드 4902를
보존한다. 컨텍스트 경로를 제거하며, 다른 API의 메서드 불일치는 공통 코드 405다.

## 로컬 검증 · 2026-10-29

- 수정 전 대상 23건 중 11건이 실패했다. 회원 404/409, 인증 401·유효성 검사,
  오류 코드 선택과 실제 Spring/H2의 없는 회원 500을 재현했다.
- 실제 컨트롤러·매퍼·advice를 사용해 등록 순서를 뒤집어도 결과가 같은지 검사했다.
  외부 호출 대신 애플리케이션 포트에서 도메인/DB 오류를 주입했다.
- 실제 Spring 컨텍스트·JPA/H2·캐시 프록시 테스트에서 회원 경로 3개 모두 캐시
  정상/장애 시 404와 code 2002, 캐시 장애 중 DB 오류 500을 확인했다.
- 최종 전체 로컬 79건, ArchUnit, Spotless, bootJar와 커밋 규칙 도구 11건이 통과했다.
  기존 `@SpyBean` deprecation과 JVM class-sharing 경고는 남아 있다.
- 로컬 Docker는 띄우지 않았다. 기존 PostgreSQL Testcontainers 테스트 1건은
  로컬 실행에서만 임시 제외했고, CI의 원래 `clean check bootJar`에는 제외하지 않는다.

JDK 17에서 새 회귀 테스트만 실행하려면 다음 명령을 사용한다.

```powershell
.\gradlew.bat test --tests "*MemberErrorResponseTest" --tests "*MemberProfileCacheFallbackTest"
```

MVC 경계 테스트는 인증 필터를 실행하지 않는다. 토큰 발급·재발급 및 로그인 실패
정책 자체를 바꾼 작업이 아니다. 실제 장애를 운영 DB/Redis에 주입하지 않는다.

## 독립 리뷰와 보완

독립 읽기 전용 리뷰는 초기 구현의 업로드 검증 메시지 소실과 컨트롤러 선택 전
인증 메서드 불일치 코드 변경을 지적했다. 두 지적을 실제 MVC 테스트로 재현했다
(24건 중 4건 실패). 공개 검증 메시지 보존과 경로 기반 405 코드 처리를 보완한 뒤
전체 79건을 통과했다. 회원/인증 경로 별칭, 두 advice 등록 순서와 컨텍스트 경로도
검증했다. 리뷰어는 테스트나 운영 확인을 실행하지 않았으며 보완은 작성자의
RED→GREEN 및 전체 검사로 검증했다. 별도 Minor 지적은 없었다.

리뷰 중 범위를 정리한 기존 동작은 다음과 같다. 필터/토큰·로그인 정책과 기존 인증
콘솔 로그는 그대로이며 이 변경으로 보안 정책/로그 정비가 검증된 것은 아니다.
이미지 조회의 기존 ResponseStatusException 매핑, 필수 헤더/파라미터·타입 불일치·
미지원 미디어·미등록 리소스의 기존 오류 처리 문제도 별도 범위다. 해당 입력의
오류 응답이 이번 작업으로 전부 정리되는 것은 아니다. 캐시 TTL·지연·무효화·
chat/list 캐시 장애 정책도 기존대로이며 모든 캐시 장애를 흡수하지 않는다.
PostgreSQL 전체 CI·이미지 발행·배포 근거는 작성자가 별도로 확인한다.

## 실제 CI·운영 확인 · 2026-10-29

최종 런타임 커밋은 `919feb590bbe3d5a33d188d887090a813ff0029b`다.
[CI 40881570424](https://github.com/5-BaeChuKimParkJo/member-service/actions/runs/40881570424)
의 전체 `./gradlew clean check bootJar`와 GHCR 이미지 발행이 성공했다. 실제 로그에서
test task 실행과 `BUILD SUCCESSFUL in 57s`를 확인했다. 로컬의 임시 Docker 테스트
제외 설정은 커밋하지 않았으며 CI에 전달하지 않았다. 기존 PostgreSQL 트랜잭션
테스트는 원래대로 전체 검사 대상이다.

자동 GitOps 커밋 `d952381d970b06d22f6f93be6dff0d99110287b2`는 account-service
이미지만 새 SHA로 갱신했다. 실제 Deployment 이미지, 새 파드 Ready=true/재시작 0,
rollout 완료와 Argo Synced/Healthy를 확인했다. Spring 기동 중 첫 50초 대기 제한은
넘겼고 초기 readiness 연결 거부 이벤트가 있었다. 이미지 다운로드·파드 상태를
확인한 후 실제 준비 완료를 다시 확인했다.

운영 HTTP 검증은 데이터 변경 없는 GET만 사용했다.

- 동일한 없는 회원 조회: 배포 전 500/code4903 → 배포 후 404/code2002,
  기존 공개 메시지 일치, JSON에 httpStatus 미포함.
- 기존 경매 판매자 조회: 200 및 판매자 UUID 일치.
- 두 외부 서비스 경로의 인증/인증번호 API 4개: 잘못된 메서드에 405/code4902.
- 실제 Chromium 데스크톱·모바일: 경매 제목·판매자 표시, 가로 넘침 없음,
  입찰·결제 POST 0건.

실제 DB/Redis 장애나 닉네임 변경·업로드·로그인 실패를 운영에 주입하지 않았다.
그 경계의 오류 처리 근거는 격리된 회귀 테스트이며 운영 검증은 정상 조회 및
읽기 전용 오류 응답 확인이다.
